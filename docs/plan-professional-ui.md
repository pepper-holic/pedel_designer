> - 비이상적 Op-Amp 매크로 모델(GBWP/슬루레이트/rail 클리핑) 완료 — 상세는 [plan-audio-domain-features.md](./plan-audio-domain-features.md) 1번 항목 참고.

## 배경

현재 앱은 기능적으로는 동작하지만(솔버, AC 해석, 프리셋 8종, 간이 스키매틱 에디터), 다음 두 가지가 "장난감처럼" 보이게 만듦:

1. **레이아웃/워크플로우가 일반 웹 폼에 가까움** — 프리셋 모드와 "직접 회로 구성" 모드가 완전히 분리된 별개 화면이고, 결과(파형/주파수응답)를 보려면 패널을 오가야 함. KiCad/LTspice 같은 실제 EDA 툴은 하나의 작업 공간(캔버스+독 패널)에서 배치→배선→파라미터 조정→시뮬레이션 결과 확인이 끊김 없이 이어짐.
2. **소자가 사실적인 회로 기호가 아님** — 현재는 소자 종류와 무관하게 전부 둥근 사각형 박스+점(단자)으로만 그려짐. 저항 지그재그, 커패시터 평행판, 다이오드 삼각형, opamp 삼각형 같은 업계 표준(ANSI, 기타 이펙터 DIY 커뮤니티 관행과 동일) 기호가 없음.

사용자 확인 사항: "페달보드 설계 관점"은 실제 페달 외관(노브/풋스위치)이나 보드 단위 배선이 아니라 **스키매틱 기호의 사실성**을 뜻함. 이번 작업의 최우선 순위는 **전체 앱 레이아웃/워크플로우 재설계**이고, 기호 사실성은 그 다음.

참고한 실제 EDA 툴 관례:
- KiCad Schematic Editor: 상단 툴바(파일/줌/편집) + 좌/우 독 패널(소자 라이브러리, Properties Manager) + 중앙 캔버스, 심볼 배치는 라이브러리에서 검색해 드래그.
- 표준 기호: 저항(ANSI 지그재그 vs IEC 사각형), 커패시터(평행판, 극성 커패시터는 곡선판), 다이오드(삼각형+바), 트랜지스터(원 안에 사선, 이미터 화살표 방향으로 NPN/PNP 구분), op-amp(삼각형 + `+`/`-` 입력).

## 목표 아키텍처: 통합 워크벤치

지금의 "프리셋 화면 / 에디터 화면" 이분법을 없애고, **하나의 스키매틱 워크벤치**로 통합한다. 프리셋은 별도 화면이 아니라 "템플릿 불러오기" 액션이 되어 같은 캔버스에 부품을 채워 넣는다 — 실제 EDA 툴에서 "예제 프로젝트 열기"와 동일한 개념.

```
┌─────────────────────────────────────────────────────────────────┐
│ 메뉴바: 파일  편집  보기  시뮬레이션                                  │  ← 새로 추가
├─────────────────────────────────────────────────────────────────┤
│ 툴바: [새 회로] [템플릿▾] │ [저항+][C+][D+][Q+][Op+][V+][GND+][Pot+] │ [▶ 실행] [줌 - +] [격자] │
├───────────────┬─────────────────────────────────────┬───────────┤
│  프로젝트/     │                                     │  속성      │
│  소자 라이브러리 │        스키매틱 캔버스 (그리드)         │  인스펙터   │
│  패널 (좌 독)   │        - 직교 배선, 접점 dot           │  (우 독)   │
│               │        - 회전/미러 가능한 부품 기호       │           │
│               │                                     │           │
├───────────────┴─────────────────────────────────────┴───────────┤
│ 결과 패널 (하단 독, 탭): [파형] [주파수 응답] [오디오 입력/실행]        │  ← 상시 표시
├─────────────────────────────────────────────────────────────────┤
│ 상태바: 선택 소자 · 넷 개수 · 시뮬레이션 상태                          │
└─────────────────────────────────────────────────────────────────┘
```

### 패널별 역할

- **좌측 독 (소자/템플릿 패널)**: 탭 2개 — "소자 팔레트"(카테고리별: 수동소자/능동소자/소스&프로브)와 "템플릿"(현재 프리셋 8종을 여기로 이동, 클릭 시 캔버스에 로드).
- **중앙 캔버스**: 그리드 배경, 확대/축소·팬, 부품 회전(R 단축키)·삭제(Delete), 직교 배선.
- **우측 독 (속성 인스펙터)**: 선택된 부품의 파라미터를 표에 가깝게 편집 (현재처럼 텍스트 인풋 나열이 아니라 라벨+단위+슬라이더/입력 병행).
- **하단 독 (결과 패널)**: 탭으로 "파형 뷰어", "주파수 응답", "오디오 입력·재생 컨트롤"을 항상 접근 가능하게. 현재처럼 시뮬레이션 실행 전에는 숨겨지는 대신, 빈 상태(placeholder)를 보여줌.
- **상태바**: 현재 선택, 넷(노드) 개수, 마지막 시뮬레이션 소요 시간/상태를 항상 노출 — 전문 툴의 "지금 뭐가 되고 있는지 보이는" 느낌의 핵심.

## 소자 기호 사실화

`editor/partDefs.ts`의 각 부품에 **기호 렌더 함수(SVG path)** 를 추가한다. 지금처럼 `<rect>` 박스 하나로 모든 종류를 그리는 대신, 부품 종류별 전용 SVG를 그린다.

| 부품 | 기호 |
|---|---|
| 저항 | ANSI 지그재그 (기타 이펙터 DIY 도면 관행과 동일) |
| 커패시터 | 평행 두 판 (극성 커패시터는 한쪽을 곡선판 + `+` 표시) |
| 인덕터 | 반원 코일 반복 |
| 다이오드 | 삼각형 + 바 (LED는 바깥으로 화살표 두 개 추가) |
| 트랜지스터(BJT) | 원 + 사선 베이스 + 컬렉터/이미터 리드, 이미터 화살표 방향으로 NPN/PNP 표시 |
| Op-amp | 우측을 향한 삼각형, `+`/`-` 입력 라벨 |
| 전압원(입력) | 원 안에 사인파 — "기타 입력 신호"임을 시각적으로 암시 |
| 접지 | 표준 접지 기호 (하강하는 3줄 수평선) |
| **포텐셔미터 (신규)** | 저항 지그재그 + 와이퍼 화살표. 게인/톤 노브 파라미터를 표현하려면 반드시 필요한데 현재 라이브러리에 없음 |

### 추가로 필요한 기반 작업

1. **회전/미러**: `PartInstance`에 `rotation: 0 | 90 | 180 | 270` 필드 추가. 단자 좌표(`dx, dy`)를 렌더링 시 회전 변환해서 계산 (`terminalPosition`, `netlistFromGraph`가 이 값을 그대로 사용하므로 좌표 계산 함수 하나만 고치면 전체에 반영됨).
2. **그리드 스냅**: 부품 드래그 시 좌표를 10px 그리드에 반올림. 배선 시각적 정렬이 훨씬 깔끔해짐.
3. **직교 배선(Manhattan routing)**: 두 단자를 잇는 선을 대각선 직선 대신 L자(또는 Z자) 2~3세그먼트로 그림. 상대 위치에 따라 "가로→세로" 또는 "세로→가로" 자동 선택하는 단순 휴리스틱으로 충분 (완전한 장애물 회피 오토라우터는 범위 밖).
4. **접점 dot**: 3개 이상의 배선이 만나는 지점에 검은 점을 그려 "연결됨"을, 단순 교차(2개 배선이 지나가기만 함)는 점 없이 표시.

## 단계별 구현 로드맵

**1단계 — 앱 셸 레이아웃 전환** (기능 변경 없이 틀만 교체)
- 상단 툴바 + 좌/우/하단 독 패널 레이아웃으로 `App.tsx` 전면 리팩터.
- 아이콘 라이브러리 도입 (`lucide-react` 등 트리셰이킹 가능한 세트) — 툴바 버튼에 텍스트 대신/함께 아이콘 사용.
- 상태바 컴포넌트 신규 추가.

**2단계 — 프리셋/에디터 모드 통합**
- "프리셋 모드"를 없애고, 프리셋을 `PartInstance[]`+`Wire[]`로 변환해 캔버스에 로드하는 `loadTemplate(preset)` 함수 작성.
- 현재 `PedalPreset.build()`가 넷리스트를 직접 반환하는 구조이므로, 프리셋 쪽에도 "그래프 배치 정보(좌표)"를 함께 정의하거나, 넷리스트→그래프 역변환 로직을 작성해야 함 (설계 결정 필요, 아래 "검토 필요 사항" 참고).
- 결과 패널(파형/주파수응답/오디오)을 하단 독으로 이동, 상시 렌더링.

**3단계 — 소자 기호 사실화**
- `editor/symbols/` 디렉터리 신설, 부품 타입별 SVG 심볼 컴포넌트 분리 (`ResistorSymbol.tsx` 등, 파일당 하나).
- `PART_DEFS`에 포텐셔미터 추가.
- `SchematicCanvas.tsx`가 박스 대신 이 심볼들을 렌더링하도록 교체.

**4단계 — 배선/그리드 개선**
- 그리드 스냅, 직교 배선 라우팅 함수, 접점 dot 렌더링.
- 회전(`R` 단축키) 구현.

**5단계 — 마감**
- 속성 인스펙터를 표 형태로 다듬기 (단위 라벨, 값 검증).
- 키보드 단축키(Delete로 삭제, 방향키로 미세 이동 등), 캔버스 줌/팬.

## 검토가 필요한 설계 결정 (구현 시작 전 확인)

1. **프리셋을 그래프로 표현하는 방법**: (a) 각 프리셋 파일에 넷리스트와 별도로 부품 좌표를 손으로 지정 (정확하지만 프리셋 8개 전부 수작업 필요), (b) 넷리스트만 두고 자동 레이아웃 알고리즘으로 좌표를 생성 (수작업은 없지만 자동배치 품질이 떨어질 수 있음). 기본적으로 (a)를 추천 — 프리셋 수가 적고, 교육적으로 "정석 회로도 모양"을 보여주는 것 자체가 가치 있음.
2. **상태 관리**: 지금은 `App.tsx`에 `useState`가 모여 있는데, 독 패널 4개가 서로 상태를 공유하는 구조가 되면 prop drilling이 늘어남. 컴포넌트 트리가 실제로 복잡해지는 시점(2단계 착수 시)에 Context 또는 가벼운 스토어(Zustand) 도입 여부를 다시 판단.
3. **아이콘 라이브러리 선택**: `lucide-react`(가장 무난) vs `@phosphor-icons/react`(더 다양한 두께) 중 택 1 — 취향 문제라 구현 시작 시 확인.

## 검증 방법

- 매 단계 후 `npm run build` + `npx vitest run`으로 기존 솔버/프리셋 회귀 없는지 확인 (이번 작업은 UI 레이어만 건드리므로 솔버 테스트는 전부 그대로 통과해야 함).
- 2단계(모드 통합) 후 8개 프리셋 전부를 템플릿으로 불러와 배선이 원래 넷리스트와 동일한 결과를 내는지 `netlistFromGraph` 유닛 테스트로 검증.
- 매 단계 후 브라우저에서 실제 조작 (부품 배치·회전·배선·프리셋 로드·시뮬레이션 실행)까지 확인.
