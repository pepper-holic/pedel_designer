# 기본기능 완성 계획 — 분해·블록 계층 / 배치·배선 / 지점별 분석 / 노브 반응

> 작성: 2026-10-27. ROADMAP Phase 0~13이 "프리셋을 통째로 불러와 분석하는" 방향으로 완성된 뒤,
> 사용자가 지적한 **기본기능 네 가지**가 실제로는 초기 형태에 머물러 있음을 코드로 확인하고 세운
> 계획. 2026-10-27 사용자 확정(§8) 후 실행 중. 이 문서가 완료되면 ROADMAP §2에 Phase 14~18로 편입한다.

## 0. 목표 — 사용자가 정의한 기본기능

1. **회로 분해 → 용도별 라이브러리 → 블랙박스/세부 회로 전환.** 많은 회로 예시를 가져와 기능 단위로
   쪼개고, 블록으로 접어서(블랙박스) 조립하거나 펼쳐서 세부 회로를 손볼 수 있어야 한다.
2. **자동 배치가 적절하고, 사용자가 통제할 수 있어야 한다.** 부품뿐 아니라 배선 경로까지.
3. **각 지점의 파형·스펙트럼 분석.** 출력 노드 하나가 아니라 회로 어느 지점이든.
4. **공학자와 연주자 양쪽.** 엔지니어는 수치·그래프로, 연주자는 노브를 돌리며 소리로 반응을 확인.
5. **설계한 회로를 실제 PCB에 어떻게 올릴지까지 만들어낸다.** (2026-10-27 추가. ROADMAP §5의 "배치/라우팅은
   범위 밖" 결정을 **뒤집는다** — 지금은 KiCad 넷리스트까지만 내보내고 풋프린트도 비어 있다.)

## 2. 전체 순서와 일정

```
Stage 0  위생 (1일)           — 큰 파일 분리, ROADMAP 갱신, 벤치 스크립트
Stage A  프로브·스펙트럼 (1주) — 목표 3. 독립적, 효과가 빨리 보임
Stage B  블록 계층 (3~4주)     — 목표 1. 핵심. 가장 크고 다른 단계의 토대
Stage C  배치·배선 (1~2주)     — 목표 2. B의 계층이 있어야 쉬워지므로 B 다음
Stage D  성능·플레이어 (3~4주) — 목표 4. D0(미리듣기)만 A 직후 끼워 넣을 수 있음
Stage E  PCB 레이아웃 (6~8주)   — 목표 5. C의 라우터·B의 블록 그룹을 물리 배치에 재사용
```

총 16~20주. 매 단계 끝에 CI(lint → typecheck → coverage → build → e2e) 녹색 유지, 파일 400줄 룰
유지, 신규 프리셋/블록은 기존 `presets-sanity.test.ts` 류 전수 검사에 자동 편입.

**확정 순서 (2026-10-27): 0 → A → D-0 → B → C → D → E.** A와 D-0는 작고 눈에 바로 보이며, B를 설계하는
동안 실제 사용 감각(프로브를 찍고 노브를 돌려 듣는)이 생겨 블록 포트/노브 노출 설계가 더 정확해진다. D와 E는 둘 다
하되, **PCB(E)는 앞 단계가 전부 끝난 다음 스텝**으로 개발한다(사용자 결정). E는 C의 격자 라우터와 B의 블록 그룹을
그대로 재사용한다.

## 4. Stage A — 프로브 · 스펙트럼 · DC 동작점 (1주)

### A-1. 데이터 모델
```ts
interface Probe { id: string; terminal: TerminalRef; label: string; color: string }
```
- 넷 이름(n1, n2)은 로드 때마다 union-find가 새로 매기므로 **단자 기준**으로 저장한다(`WiringPreset.outputTerminal`과
  같은 이유). 해석 시 `GraphNetlist.terminalNet`으로 넷을 찾는다.
- `CircuitSnapshot`/`StoredCircuit`에 `probes?: Probe[]` 추가. 선택적 필드라 schemaVersion은 1 유지(누락 시 `[]`).
- 기존 `outputNode`는 그대로 둔다(BOM/THD/체인이 쓰는 "최종 출력"의 의미). 프로브는 "보고 싶은 지점" 추가 개념.

### A-2. 캔버스 조작
- 툴바에 "프로브" 토글(단축키 P). 켜진 상태에서 단자나 배선을 클릭하면 프로브가 생기고 색 마커 + 라벨이 그 자리에
  그려진다. 마커 클릭으로 제거, 라벨 더블클릭으로 이름 변경(= 넷에 사용자 이름을 주는 유일한 방법).
- 새 파일 `editor/ProbeLayer.tsx`(마커 렌더링), `editor/useProbes.ts`(추가/제거/라벨, 넷 해석).

### A-3. 분석 탭 변경
- **주파수 응답**: `outputNode` 한 곡선 → 프로브마다 한 곡선 겹쳐 그리기. `SweepTab`이 이미 쓰는 다중 곡선
  `viz/FrequencyResponse.tsx` 경로 재사용. 프로브가 없으면 지금처럼 출력 노드 한 곡선.
- **파형**: 프로브 지점을 라벨 이름으로 맨 앞에, 나머지 넷은 "전체 보기" 접힘 아래로.
- **스펙트럼(신규 탭)**: 마지막 트랜지언트 결과의 프로브별 FFT.
  - `core/analysis/spectrum.ts`: `computeSpectrum(signal, sampleRate, { fftSize, window: "hann" })` →
    `{ frequenciesHz, magnitudeDb }`. 기존 `fft.ts` 재사용. 여러 프레임 평균(Welch)으로 잡음 완화.
  - `viz/Spectrum.tsx`: 로그 주파수축 20Hz~20kHz, dB 세로축, 프로브 색으로 겹쳐 그림, 커서 호버로 값 표시.
  - `editor/SpectrumTab.tsx` + `dockTabs.tsx` 등록. 시뮬레이션 결과가 없으면 "실행하면 표시" 안내.
- **DC 동작점**: `editor/operatingPoint.ts` — 입력원을 0V로 두고 DC를 풀어 넷별 전압을 돌려준다(`powerDraw.ts`가
  이미 같은 방식으로 DC를 푼다). 캔버스 옵션 "바이어스 전압 표시"를 켜면 프로브 마커 옆(또는 전 넷)에 "4.52V"
  식으로 표시. 트랜지스터 회로 설계의 기본 수치.

## 5. Stage B — 블록 계층: 분해 · 라이브러리 · 블랙박스 (3~4주, 핵심)

### B-1. 데이터 모델 (schemaVersion 1 → 2)
```ts
type PortKind = "in" | "out" | "supply" | "ground" | "bias" | "aux";
interface BlockPort { id: string; label: string; kind: PortKind; terminal: TerminalRef } // 내부 단자 = 포트
interface BlockParam { id: string; label: string; partId: string; paramKey: string }   // 노브로 노출할 내부 파라미터
interface BlockInstance {
  id: string; defId: string | null;        // null = 사용자가 묶어 만든 블록
  label: string; category: BlockCategory;
  ports: BlockPort[]; params: BlockParam[];
  collapsed: boolean; x: number; y: number; rotation: Rotation;  // 접힌 기호의 위치
  parentBlockId?: string;                  // 중첩. 모델은 허용, UI는 v1에서 한 단계만
}
```
- `PartInstance.blockId`는 유지. `Wire`/`TerminalRef`는 **바꾸지 않는다**: 접힌 블록은 "단자가 곧 포트인 가짜 부품"으로
  취급해, 포트에 닿은 배선은 `{ partId: blockId, terminalId: portId }`로 저장된다. `netlistFromGraph`가 포트 →
  내부 단자로 한 번 치환하면 솔버는 아무것도 모른다.
- `BlockCategory` 확장: `"buffer" | "gain" | "clipping" | "tone" | "load" | "power" | "fuzz" | "output" | "input" | "custom"`.
- 마이그레이션(`circuitStorage.ts`): v1 블록은 `ports: [], params: [], collapsed: false`, 위치는 소속 부품의
  바운딩 박스로 계산. 기존 저장 데이터·배선 프리셋 25종·회로 파일이 그대로 열려야 한다(테스트로 고정).

### B-2. 캔버스: 접기/펼치기
- 접힘: 카테고리 색 상자 + 라벨 + 좌/우/상/하에 포트 핀(in 왼쪽, out 오른쪽, supply 위, ground 아래) + 노출 노브 이름.
  소속 부품·내부 배선은 숨기고, 외부에서 내부 단자로 들어오던 배선은 포트 위치로 끝점을 옮겨 그린다(렌더링만, 전기적
  동일).
- 펼침: 지금의 색칠 영역 그대로, 경계에 포트 표식만 추가.
- 더블클릭 또는 인스펙터 버튼으로 토글. 접힌 블록 드래그 = 소속 부품 전부 이동. 선택/복사/삭제가 블록 단위로 동작.
- `SchematicCanvas.tsx`가 아니라 새 `editor/BlockSymbol.tsx`·`editor/blockGeometry.ts`에 둔다(400줄 룰).

### B-3. 조작: 묶기 · 해제 · 저장 · 노브 노출
- **선택 → 블록으로 묶기**(Ctrl+G): 선택 밖 부품과 배선으로 이어진 단자를 자동으로 포트로 뽑는다. 종류 추정:
  입력원 쪽 신호 깊이가 얕은 쪽이 in, 깊은 쪽이 out, 전원 소자에 닿으면 supply, 접지는 ground. 사용자가 인스펙터에서
  고친다.
- **블록 해제**(Ctrl+Shift+G): 포트 배선을 내부 단자 배선으로 되돌리고 블록 레코드를 지운다.
- **내 블록으로 저장**: `BlockDef`와 같은 형태(넷리스트 + 포트 + 파라미터 + 기본 배치)를 localStorage `pedal-designer:blocks`
  와 `.json` 파일로. 라이브러리 탐색기에 "내 블록" 그룹 추가.
- **노브 노출**: 인스펙터에서 소속 부품의 파라미터를 골라 `BlockParam`으로 올리면 접힌 기호에 노브 이름이 보이고,
  Stage D의 플레이어 뷰가 이 목록을 그대로 노브로 쓴다. 포텐셔미터·스위치는 기본으로 노출.

### B-4. 블록 라이브러리 확장 (6종 → 20종 안팎)
`blockDefs.ts`를 카테고리별 파일로 쪼갠다(`editor/blocks/*.ts`, 회로 1개 = 파일 1개 원칙). 각 정의에 `ports`를
명시. 신규 후보(전부 기존 소자로 가능, 전원 포트는 `role: "supply"` 덕분에 입력원 탐색과 충돌하지 않음):

| 카테고리 | 블록 |
|---|---|
| input | 입력 커플링(캡+풀다운), 입력 버퍼(이미터 팔로워 / JFET 소스 팔로워) |
| power | 9V 전원 + 가상 접지 분압(Vref 4.5V), 디커플링 |
| gain | BJT 공통 이미터 단(바이패스/언바이패스 선택), JFET 공통 소스 단, op-amp 논인버팅 단 |
| clipping | 4-다이오드 피드백 클리퍼, 션트 클리퍼(실리콘/게르마늄/LED 선택), op-amp 레일 클리핑 단 |
| fuzz | 2-트랜지스터 직결 피드백 코어(퍼즈페이스형), 3-트랜지스터 코어(Tone Bender형), Big Muff형 게인+클립 단 |
| tone | Fender 3노브 톤스택, Marshall 톤스택, Big Muff 톤, 단일 RC 톤(기존), Baxandall(배선 프리셋에서 이식) |
| output | 볼륨 포트 + 출력 커플링, 출력 버퍼 |
| load | 케이블+앰프 부하(기존), 픽업 소스(배선 쪽에서 이식) |

### B-5. 프리셋 23종 분해 (라이브러리화의 실체)
두 가지 길이 있고 **주석(annotation) 방식을 추천**한다:
- (추천) `PedalPreset.blocks?: { id, label, category, elementIds: string[], ports, params }[]`를 각 프리셋에 추가.
  넷리스트는 그대로라 기존 동작 테스트(`*-behavior.test.ts`)가 한 줄도 안 바뀌고, `graphFromNetlist`가 이 주석으로
  `BlockInstance`를 만든다. 분해 결과가 틀리면 블록만 틀리고 소리는 안 틀린다.
- (대안) 프리셋을 블록 조합으로 재작성. 깔끔하지만 23종 전부 소리 회귀 위험을 안는다. B-4 라이브러리가 충분히 검증된
  뒤 일부만 전환.

진행 순서(같은 계보끼리 묶어 블록 재사용을 확인): op-amp 드라이브 계열(opamp-drive, TS9, RAT, Boss, Distortion+)
→ 투명 오버드라이브 계열(Klon, King of Tone, Timmy, Bluesbreaker, OCD) → 퍼즈 계열(fuzz-germanium, Big Muff,
Tone Bender, 옥타브 퍼즈) → 부스트/톤(LPB-1, Rangemaster, JFET 부스트, 톤 틸트, 능동 EQ, 버퍼, 클리퍼 2종,
다단 드라이브).

검증 테스트 `tests/editor/preset-blocks.test.ts`: 모든 소자가 정확히 한 블록에 속하거나 명시적 최상위, 포트 단자가
실재, 포트를 통해서만 블록 밖과 연결(누수 배선 0), 접힘/펼침 왕복 후 넷리스트 동일(`findEquivalentNode` 재사용).
프리셋 배열에 등록만 하면 자동 편입되는 기존 관례를 따른다.

### B-6. 완료 기준
- TS9 스타일을 로드하면 입력 버퍼 / 게인·클리핑 / 톤 / 출력 4개 블록으로 보이고, 접으면 핀 달린 상자 4개와 배선만
  남으며, 펼치면 세부 회로를 고칠 수 있다.
- 빈 캔버스에 블록 라이브러리에서 전원 + JFET 부스트 + 션트 클리퍼 + Fender 톤스택 + 출력 볼륨을 끌어다 포트끼리
  이어 새 페달을 만들고, 그걸 "내 블록"으로 저장해 다른 회로에서 접힌 채 재사용할 수 있다.
- 23종 전부 블록 주석 완료, 블록 라이브러리 20종, 기존 366개 + 신규 테스트 전부 통과, 저장 데이터 v1 → v2 자동 변환.

### B-7. 리스크
- **포트 자동 추출의 모호함**(한 단자가 in이자 bias인 경우 등): 추정은 힌트일 뿐, 인스펙터에서 항상 고칠 수 있게.
- **접힌 블록 배선 렌더링**: 전기적 모델은 안 바뀌므로 위험은 시각 쪽에만 있음. Stage C의 라우터가 해결.
- **중첩 블록**: 모델은 `parentBlockId`로 열어두되 UI는 한 단계만. 두 단계 이상은 사용자가 필요로 할 때.

## 6. Stage C — 계층 배치 · 배선 제어 (1~2주)

- **C-1. 배선 경유점**: `Wire.waypoints?: { x: number; y: number }[]`. `geometry.ts`의 `computeWirePaths`가 있으면 그대로
  쓰고 없으면 자동. 배선 세그먼트를 드래그하면 경유점이 생기고, 인스펙터 "경로 초기화"로 되돌린다. schemaVersion 2에
  같이 포함(B-1과 동시 도입).
- **C-2. 계층 배치**: `graphFromNetlist`의 열/행 배치를 두 수준으로. 블록을 슈퍼노드로 보고 신호 깊이 순으로 좌→우
  배치 → 각 블록 안에서 기존 BFS/바리센터 → 블록 상자 크기를 내용에 맞춰 키우고 겹침 해소. 블록 없는 부품은 기존대로.
  새 파일 `editor/layout/hierarchical.ts`.
- **C-3. 장애물 회피 라우터**: 10px 격자 A*, 부품 몸체·접힌 블록 상자를 장애물로, 꺾임마다 비용. 경로를 못 찾으면
  기존 2-bend로 폴백. `editor/routing/astar.ts`. 넷 30개 규모에서 수 ms 이내가 목표(벤치에 포함).
- **C-4. 자동 정렬 버튼 + 고정**: 사용자가 끌어 놓은 부품은 `pinned: true`가 되고, "자동 정렬"은 고정 안 된 것만
  다시 놓는다. "전부 풀기"로 초기화.
- 완료 기준: 수동 좌표를 박아 둔 프리셋 5종 중 3종 이상에서 `layout` 오버라이드를 지워도 교차가 늘지 않는다
  (교차 수를 세는 테스트로 고정). 사용자가 배선 하나를 끌어 경로를 바꾸고 저장·복원할 수 있다.

## 7. Stage D — 솔버 성능 · 실시간 · 플레이어 모드 (3~4주)

### D-0. 임시 미리듣기 (2일, Stage A 직후 가능)
노브(인스펙터 슬라이더·포트 값)를 **놓는 순간** 내장 신호 0.5초를 1x 오버샘플링으로 워커에서 돌려 자동 재생.
현재 속도로도 0.3~2초 안에 소리가 나온다. "돌리면 들린다"의 절반을 성능 작업 전에 준다. 설정에서 끌 수 있게.

### D-1. 솔버 10배 이상 (2주)
현재 `transient.ts`는 서브스텝마다, Newton 반복마다 `MnaSystem`을 새로 만들어 전체 스탬프 + 조밀 가우스 소거를 한다.
순서대로:
1. **토폴로지·선형 스탬프 1회**: R/L/C/이상 op-amp/전압원의 행렬 기여는 dt가 고정이면 상수. 기본 행렬을 한 번 만들고,
   샘플마다 `copy` 후 비선형 소자(다이오드/BJT/JFET/비이상 op-amp)와 시간 이력 항만 덧스탬프.
2. **할당 제거**: `Float64Array` 사전 확보, 샘플 루프 안에서 `Map`·문자열 키 조회 금지(소자 → 노드 인덱스를 미리 배열로).
3. **LU + 부분 피벗**을 제자리에서, 해 벡터 재사용.
4. **Newton 개선**: 작은 변화량 조기 종료, 스텝 감쇠(damping) — Tone Bender의 미수렴 28샘플 해결 겸.
5. `npm run bench`로 측정. 목표: TS9 1x ≤ 0.1s/s, King of Tone 4x ≤ 1.5s/s (≈10배). 못 미치면 그때 WASM 검토.
결과 수치 동일성은 기존 솔버 테스트 전부(동일 입력 → 동일 출력, 오차 1e-9)로 고정.

### D-2. AudioWorklet 실시간 (1주)
- 워클릿 안에서 128샘플 블록마다 솔버 실행, 노브 변경은 메시지로 파라미터만 갱신(토폴로지 변경 시 재빌드).
- 회로별 CPU 비율을 측정해 실시간이 안 되는 회로는 자동으로 D-0 미리듣기로 폴백.
- 입력: 내장 신호 루프, 업로드 파일 루프, (선택) 마이크 — 마이크는 `vercel.json`의 `Permissions-Policy: microphone=()`를
  바꿔야 하므로 사용자 결정 사항.

### D-3. 플레이어 뷰 (1주)
- "회로도 / 연주" 토글. 연주 뷰는 회로도를 숨기고 페달 전면판 형태로 **B-3에서 노출한 노브·스위치**만 보여준다.
- 노브를 돌리면 D-2가 있으면 즉시, 없으면 D-0 미리듣기. 옆에 작은 주파수 응답과 스펙트럼(Stage A)을 같이 띄워
  "소리가 왜 바뀌었는지"를 엔지니어 시각과 연결.
- 완료 기준: 연주 뷰에서 TS9 드라이브 노브를 돌리며 끊김 없이 듣고, 같은 화면에서 스펙트럼이 따라 움직인다.

## 7-E. Stage E — PCB 레이아웃 생성 (6~8주)

페달 DIY는 **스루홀(THT) 부품, 단면 또는 양면 보드, 그리고 스트립보드(베로보드)가 주류**다. 그래서 "완전 자동
오토라우터"를 처음부터 겨냥하지 않고, 커뮤니티가 실제로 쓰는 산출물 순서대로 올라간다. SMD·다층 보드·임피던스 제어는
범위 밖으로 명시한다.

### E-1. 풋프린트/패키지 배정 (3일, 언제든 가능)
- `PartInstance.params`가 아니라 별도 `footprintId?: string`로 둔다(전기 시뮬레이션과 무관한 물리 속성이라 분리).
- `editor/pcb/footprints.ts`: 페달 DIY에 쓰는 THT 풋프린트 라이브러리 ~25종. 각 항목은 `{ id, kicadName, pads:
  [{ id, x, y, drillMm, ringMm }], courtyard: { w, h } }`를 가진다(mm 단위).

| 소자 | 기본 풋프린트 | 선택지 |
|---|---|---|
| 저항 | 축형 1/4W, 10.16mm 피치 | 7.62mm, 세워 꽂기(vertical) |
| 커패시터 | 필름 박스 5mm 피치 | 2.5/7.5mm, 세라믹 2.5mm, 전해 2mm/2.5mm 방사형 |
| 다이오드 | 축형 DO-35 7.62mm | DO-41 10.16mm, LED 3mm/5mm |
| BJT/JFET | TO-92 (EBC/ECB 핀 순서는 모델별) | TO-18(게르마늄) |
| Op-amp | DIP-8 | DIP-14 |
| 포텐셔미터 | 16mm PCB 마운트 3핀 | 9mm, 패널 마운트(와이어 패드 3개) |
| 스위치(SPST~DPDT) | 3PDT/DPDT 풋스위치 패드 | 토글 패널 마운트(와이어 패드) |
| 블레이드/로터리 | 와이어 패드만(오프보드) | — |
| 픽업·전압원·접지 | 오프보드 패드(IN/OUT/9V/GND) | — |

- `kicadNetlist.ts`의 `(footprint "")`를 KiCad 표준 이름(`Resistor_THT:R_Axial_DIN0207_L6.3mm_D2.5mm_P10.16mm_Horizontal`
  등)으로 채운다. 이것만으로도 KiCad에서 바로 보드를 그릴 수 있게 된다.
- BOM에 패키지 열 추가. 인스펙터에 "풋프린트" 드롭다운.
- 완료 기준: TS9 프리셋을 KiCad 8에 임포트하면 풋프린트 미지정 경고 0건.

### E-2. 스트립보드(베로보드) 레이아웃 생성기 (2~3주)
DIY 커뮤니티(Tagboard Effects, Dirtbox Layouts 류)의 사실상 표준 산출물이고, 문제 구조가 PCB 라우팅보다 훨씬 작다:
부품은 2.54mm 격자 구멍에, 넷은 가로 구리 스트립에, 넷 분리는 스트립 컷으로.
- 모델: `{ rows, cols, strips(row=net 할당), cuts: {row, col}[], jumpers: {row, colA, colB}[], parts: {id, row, col, orientation} }`.
- 알고리즘: 블록(Stage B) 단위로 좌→우 신호 흐름 순서를 정하고, 넷마다 스트립을 배정한 뒤 부품을 격자에 놓는
  **탐욕 + 국소 탐색**(총 컷 수·점퍼 수·보드 면적 최소화). 수십 부품 규모라 브라우저에서 1초 안에 끝난다.
- 검증: 생성된 보드에서 넷리스트를 역추출해 원 회로와 동일한지 테스트(`netlistFromGraph`와 `findEquivalentNode` 재사용).
  **생성 결과가 틀리면 소리가 아니라 빌드가 틀리므로 이 역검증이 필수.**
- 출력: 캔버스 하단 "스트립보드" 탭에 인터랙티브 보드(부품 드래그로 재배치, 컷 클릭 토글, 재검증 즉시), 1:1 인쇄용
  SVG/PDF(위에서 본 부품면 + 뒤집은 구리면), 텍스트 빌드 노트(컷 좌표 목록, 점퍼 목록).
- 완료 기준: 프리셋 23종 전부 자동 생성 → 역검증 통과. LPB-1·Rangemaster 같은 소형 회로는 커뮤니티 레이아웃과 비슷한
  크기(±30%).

### E-3. PCB 자동 배치 + 라우팅 (3~4주)
- **배치**: Stage C의 계층 배치를 그대로 초기값으로 쓴다(블록 = 물리 그룹, 신호 흐름 좌→우). 그 위에 풋프린트 코트야드
  겹침 제거와 넷 길이 최소화를 위한 힘 기반(force-directed) 미세 조정. 포텐셔미터·풋스위치·잭은 보드 가장자리
  고정(사용자가 핀 고정 가능 — C-4의 `pinned`와 동일 개념).
- **라우팅**: C-3의 격자 A*를 확장. 격자 0.635mm(2.54/4), 패드·트랙 폭·클리어런스를 장애물 비용으로, 단면 보드 우선,
  못 푸는 넷은 점퍼 와이어(DIY 관례) 또는 양면 비아. 넷 순서는 짧은 것부터, 실패 시 rip-up & retry 몇 회.
- **DRC**: 클리어런스, 최소 트랙 폭, 미연결 넷, 드릴 겹침. 결과를 기존 DRC 탭에 "PCB" 심각도 그룹으로 합류.
- **출력**:
  - `.kicad_pcb` S-expression(KiCad 8 포맷) — 사용자가 KiCad에서 마무리할 수 있는 길. Gerber보다 이걸 먼저 하는 이유는
    **수정 가능한 형태**라서다.
  - 1:1 인쇄 SVG/PDF(토너 전사용 미러 구리면, 부품면 실크).
  - Gerber(RS-274X)+Excellon은 KiCad에서 뽑는 것을 기본으로 하고, 직접 생성은 E-3 완료 뒤 수요가 있으면.
- 완료 기준: 프리셋 23종 중 부품 15개 이하 회로는 점퍼 ≤2개로 단면 완주, 전부 DRC 통과, KiCad 임포트 시 넷 불일치 0.
  더 큰 회로(Big Muff·Tone Bender·King of Tone)는 양면 또는 점퍼 허용으로 완주.

### E-4. 인클로저 드릴 템플릿 (1주)
- 1590A/1590B/125B/1590BB 외형과 포트·풋스위치·잭·LED 위치를 1:1 PDF로. 포트 위치는 Stage B-3의 노출 노브
  목록에서, 잭/스위치/DC는 표준 위치 기본값 + 드래그 조정.
- 보드 외형이 선택한 인클로저 내부에 들어가는지 검사(E-3 배치의 면적 제약으로 되먹임).

### E-5. 리스크와 범위 밖
- 자동 라우터는 "KiCad를 대체"가 아니라 "**KiCad를 열기 전에 80%를 끝낸다**"가 목표. 완전 자동 완주를 보장하지 않고,
  남은 넷은 사용자가 보드 탭에서 끌어 긋거나 KiCad에서 마무리한다.
- SMD, 4층 이상, 임피던스/열 해석은 범위 밖으로 명시.
- 풋프린트 핀 순서 실수(특히 TO-92 EBC/ECB, 전해 극성)는 빌드 실패로 직결되므로, 소자 모델(`deviceModels.ts`)마다
  핀 순서를 데이터로 갖고 테스트로 고정한다.

## 8. 결정 사항 (2026-10-27 확정 — 전부 추천안 채택)

1. **착수 순서**: 0 → A → D-0 → B → C → D → E.
2. **프리셋 분해 방식**(B-5): 주석 방식. 넷리스트는 그대로, 블록 소속만 추가.
3. **중첩 블록 깊이**: 모델은 열어두고 UI는 한 단계만.
4. **플레이어 입력 소스**: 내장 신호/파일만. 마이크는 배포 헤더 변경이 필요해 보류.
5. **schemaVersion 2 마이그레이션**: 기존 localStorage·회로 파일 자동 변환.
6. **PCB 산출물 순서**(Stage E): 스트립보드 먼저, 그다음 PCB 배치·라우팅.
7. **PCB 출력 포맷**: `.kicad_pcb` + 1:1 PDF/SVG. Gerber는 KiCad에서.
8. **D와 E**: 둘 다 한다. PCB(E)는 0~D가 전부 끝난 뒤 다음 스텝.

## 9. 이 계획이 바꾸지 않는 것

- 솔버의 수학(MNA/Newton/적분법)과 소자 모델. D-1은 같은 답을 더 빨리 내는 작업이다.
- 넷리스트 포맷, `Wire`/`TerminalRef` 타입, 프리셋의 `build()`/`inputSourceId`/`outputNode` 계약.
- BOM/KiCad export, DRC, 몬테카를로, 체인 — 블록은 평면 넷리스트로 풀린 뒤 들어가므로 그대로 동작한다.
  (Stage E는 KiCad export의 풋프린트를 채우고 보드 출력을 **추가**하는 것이지 넷리스트 export를 바꾸지 않는다.)
