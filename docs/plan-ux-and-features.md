## 1. 기능 공백 — 실사용을 막는 것 (우선순위 높음)

### 1-1. ✅ 와이어를 지울 수 없다 — 해결 (2026-09-07)

- 근거: `selectedWire` / `onDeleteWire` / `removeWire` — 코드베이스 전체에 **하나도 없음**.
  `handleDeleteSelected`([SchematicEditor.tsx:185](../apps/web/src/editor/SchematicEditor.tsx))는
  파트만 지우고, 그 파트에 붙은 와이어를 같이 지운다. 와이어 단독 선택 UI가 존재하지 않는다.
- 결과: 배선을 잘못 그으면 **Ctrl+Z 말고는 복구 수단이 없다.** 여러 단계 뒤에 발견하면
  중간 작업까지 전부 되감아야 한다. 배선이 핵심 조작인 앱에서 이건 기능 공백이다.
- **해결**: 와이어마다 투명한 12px 히트박스 path를 겹쳐 클릭 대상으로 삼고, 선택 시 accent 색 3px로 강조.
  부품/배선 선택은 상호 배타적이라 Delete와 인스펙터가 항상 하나만 대상으로 한다. 인스펙터는 배선 선택 시
  양 끝 단자 + 삭제 버튼만 노출. 테스트 3개(선택/삭제/undo 복원) 추가.

### 1-2. ✅ 프리셋 파라미터가 UI에 노출되지 않는다 — 해결 (2026-09-07)

- 근거: `handleLoadTemplate`이 `preset.build(preset.defaultParams)`만 호출
  ([SchematicEditor.tsx:124](../apps/web/src/editor/SchematicEditor.tsx)). 로드 후에는 캔버스
  그래프가 진실이 되므로 `defaultParams`를 다시 쓸 길이 없다.
- 결과: **이미 구현되고 테스트까지 통과한 기능을 사용자가 쓸 수 없다.**
  - King of Tone 스타일의 `clipMode: 1`(션트 클리핑 분기) → 접근 불가
  - OCD 스타일의 `brightSwitch: 1`(트레블 브리드 분기) → 접근 불가
  - 두 분기 모두 전용 회귀 테스트까지 있는데 UI 경로가 없다.
- **해결**: `PedalPreset`에 옵셔널 `variants?: { id, label, params }[]` 추가.
  `build()`가 분기하는 프리셋이 자기 분기를 **이름 붙여** 선언하고, 라이브러리 탐색기가 그 프리셋 아래에
  들여쓴 행으로 **항상** 노출한다(선택 후 펼치는 방식이면 안 보이던 문제가 그대로라 항상 표시).
  로드 시 `defaultParams` 위에 `variant.params`를 덮어씌운다. 저장 포맷 변경 없음.
- 남은 것: 나머지 프리셋의 일반 부품값(`gainResistance` 등)은 여전히 로드 후 캔버스에서만 편집 가능하다.
  이건 캔버스가 진실인 현재 구조와 일관되므로 의도된 상태로 둔다.

### 1-3. ✅ 회로를 파일로 저장/불러올 수 없다 — 해결 (2026-09-07)

- 현재: localStorage 자동저장 슬롯 **1개**뿐. 여러 회로 보관, 백업, 공유 불가.
- 제안: `CircuitSnapshot`이 이미 순수 데이터라 **JSON export/import는 거의 공짜**.
  `circuitStorage.ts`에 `schemaVersion`도 이미 있어 마이그레이션 훅도 준비돼 있다.
- **해결**: 툴바에 "회로 저장"/"회로 열기" 추가. `circuitFile.ts`가 자동저장용 관대한 파서 위에
  임포트 전용 검증을 얹는다 — 에디터가 매 렌더 `PART_DEFS[part.type].terminals`를 인덱싱하므로
  모르는 소자나 없는 단자를 가리키는 배선이 들어오면 메시지 대신 캔버스가 죽기 때문이다.
- 남은 것: 여러 슬롯(이름 붙여 저장), URL 해시 공유.

### 1-4. ✅ DRC(회로 검사)가 없다 — 해결 (2026-09-07)

떠 있는 단자, 접지 없음, 입력 소스 없음 같은 문제를 앱이 **아무 말도 안 한다.**
시뮬레이션이 그냥 안 되거나 이상한 값이 나올 뿐이라 초보자는 원인을 못 찾는다.

검사 항목 후보 (전부 `netlistFromGraph` 결과만 보면 계산 가능):

| 검사 | 판정 근거 |
|---|---|
| 접지 부품 없음 | `groundParts.length === 0` |
| 입력 신호원 없음 | `inputSourceId === null` |
| 출력 노드 미선택 | `outputNode === ""` |
| 떠 있는 단자 (아무 와이어도 안 붙음) | union-find에서 자기 자신이 유일한 원소인 넷 |
| 어느 소자와도 연결 안 된 고립 부품 | 위와 동일 판정 |
| 전압원 단락 (양 단자가 같은 넷) | `nodes[0] === nodes[1]` |

- **해결**: 하단 도크 "검사" 탭. 심각도를 나눈 게 핵심 — 2단자 소자의 떠 있는 다리는 전류가 안 흘러
  아무 일도 안 하므로 **오류**지만, 포트/스위치의 남는 러그는 톤 포트 세 번째 러그나 푸시풀 미사용
  접점처럼 실제 배선에서 흔한 의도적 구성이라 **경고**로만 표시한다. 문제 항목에서 해당 부품으로 점프 가능.
  회귀 검사로 기존 페달 19종 + 배선 22종 전부 DRC 오류 0건임을 테스트에 넣었다.

## 2. UI/UX — 실측 근거 있는 항목

### 2-1. ✅ "화면 맞춤(fit to view)"이 없다 — 해결 (2026-09-07)

- 근거: `SchematicCanvas.tsx`에 `fit` 관련 코드 없음. 줌 컨트롤은 `+ / − / 리셋`뿐.
- 실측: 1600×950 뷰포트에서 TS9 스타일 프리셋을 로드하면 **회로 하단이 캔버스 밖으로 잘린다.**
  사용자가 직접 축소하거나 스크롤해야 전체가 보인다.
- 기타 배선까지 들어오면 회로가 지금보다 훨씬 커지므로
  ([plan-guitar-wiring.md](./plan-guitar-wiring.md) §8) **Phase 9 이전에 처리하는 게 맞다.**
- **해결**: `geometry.ts`에 순수 함수 `fitView(bounds, viewport, options)` 추가(테스트 5개), 캔버스 줌
  컨트롤에 "화면 맞춤" 버튼 + 회로가 통째로 교체될 때 자동 fit. `maxZoom` 기본값 1이라 부품 2개짜리
  회로가 캔버스를 채우도록 확대되지 않는다. 실측: TS9(8부품)·다단 드라이브(14부품) 100%,
  Big Muff 스타일(34부품) 97%에서 전 부품이 뷰포트 안. (회로가 더 커지면 미니맵은 여전히 후보)

### 2-2. 🟡 좁은 폭에서 3-pane이 무너지며 캔버스가 화면 밖으로 밀린다

- 실측: 브라우저 폭 785px에서 프리셋 목록을 열고 항목을 클릭하면 **왼쪽 사이드바가 화면을 전부
  차지하고 캔버스가 뷰포트 밖으로 나간다.** 클릭이 성공했는지조차 화면상 확인되지 않는다.
- ROADMAP 2026-09-05 항목에서 모바일 안내 배너를 추가했지만, 이건 "터치가 어렵다"가 아니라
  **레이아웃이 깨져서 작업 결과가 안 보이는** 별개 문제다.
- 제안: 좁은 폭에서는 사이드바를 오버레이/드로어로 전환하고, 항목을 고르면 자동으로 닫아
  캔버스가 보이게 한다. 최소한 프리셋 로드 후 캔버스로 스크롤.

### 2-3. ✅ 노브를 실시간으로 못 돌린다 — 확인 결과 이미 동작 중

- 현재: 포텐셔미터 `position`을 인스펙터에서 **숫자 입력**으로만 바꾼다.
- 이 앱의 가장 큰 매력은 "톤 노브를 돌리면서 주파수 응답이 실시간으로 움직이는 것"인데,
  그 경험이 지금은 없다. `acResult`가 이미 `graph` 변경에 반응하므로 **슬라이더로 바꾸기만 하면
  실시간 갱신은 저절로 된다.**
- **정정**: 실제로 확인해보니 `PARAM_META`의 `position`에 이미 `slider`가 설정돼 있어 인스펙터가
  슬라이더를 렌더하고 있었고, 브라우저에서 슬라이더를 움직이면 주파수 응답이 즉시 갱신된다.
  즉 이 항목은 **처음부터 동작하고 있었다** — 백로그 작성 시 인스펙터를 숫자 입력으로 잘못 본 것이다.
  스위치는 2026-09-07에 위치 드롭다운을 추가하면서 같은 경로에 편입됐다.
- 남은 것: 드래그 중 undo 스텝이 매번 쌓이는 문제(드래그 이동은 `replacePresent`를 쓰는데 슬라이더는
  안 씀). 실사용에 지장은 없어 후순위.

### 2-4. ✅ 파라미터 스윕을 겹쳐 볼 수 없다 — 해결 (2026-09-07)

- "톤 노브 0 / 25 / 50 / 75 / 100%의 주파수 응답"을 한 그래프에 겹쳐 그리는 기능.
  몬테카를로 패널이 이미 밴드(범위)를 겹쳐 그리므로 **`FrequencyResponse.tsx`가 다중 곡선을
  받을 준비가 부분적으로 돼 있다.**
- **해결**: 하단 도크 "노브 스윕" 탭. 포텐셔미터는 0/25/50/75/100%, 스위치는 실제 디텐트 수만큼
  곡선을 겹쳐 그린다. 출력 노드는 넷 이름이 아니라 **단자로 앵커링**해 단계마다 다시 해석한다 —
  스위치 스윕은 매 단계 회로를 바꾸고 넷 이름은 그래프마다 배정되므로, 안 그러면 셀렉터 스윕이
  엉뚱한 노드를 그리거나 출력을 잃는다.

### 2-5. 🟢 편집 편의 기능 부재

| 없는 것 | 영향 |
|---|---|
| 다중 선택 (드래그 박스) | 여러 부품 한번에 이동/삭제 불가 |
| 복사/붙여넣기·복제 (Ctrl+C/V/D) | 같은 클리핑 페어를 반복 배치할 때 매번 처음부터 |
| 캔버스 인라인 값 편집 (더블클릭) | 값 하나 고치려면 인스펙터 왕복 |
| 정렬/배분 | 배선이 지저분해지는 원인 중 하나 |
| 캔버스 키보드 조작 | 부품 선택·이동이 마우스 전용 = 접근성 공백 |

### 2-6. 🟢 오디오 A/B 비교 없음

파형 탭에서 트레이스별로 따로 재생만 가능. **원본 ↔ 처리음을 번갈아(A/B) 듣는 버튼**이
드라이브 페달 시뮬레이터에서는 거의 필수 조작이다. 루프 재생, 구간 반복도 후보.

### 2-7. 🟢 내장 테스트 신호 없음

지금은 사용자가 WAV를 업로드해야만 시뮬레이션을 돌릴 수 있다.
내장 기타 리프 샘플 / 사인 스윕 / 임펄스를 **원클릭으로** 제공하면 첫 사용 경험의 벽이 크게 낮아진다.
(THD·몬테카를로·체인은 이미 합성 신호를 쓰므로 생성 코드가 일부 있다.)

| **Blues Driver류** | JFET + 디스크리트 클리핑 | 기존 JFET |
| **트루 바이패스 vs 버퍼드 바이패스 A/B** | **`switch` 소자가 생기면 가능** — 페달 순서·버퍼 논쟁을 그래프로 결론내는 콘텐츠 | `switch` (Phase 10) |
| **옥타비아/옥타퍼즈류** | 트랜스포머 기반 → **상호 인덕턴스 필요** | 신규 소자 |

### 4-3. `variant` 파라미터 패턴을 표준화할 것

위 후보 중 여러 개(퍼즈페이스 Si/Ge, Muff 3종, TS808/TS9)가 **"같은 토폴로지 + 다른 부품값"**이다.
King of Tone의 `clipMode`, OCD의 `brightSwitch`가 이미 같은 문제를 각자 방식으로 풀고 있으므로,
`build(params)` 안의 분기를 **파라미터 프리셋 목록**으로 일반화하는 게 낫다.

단, **§1-2(프리셋 파라미터 UI 부재)를 먼저 해결하지 않으면 아무리 변종을 늘려도 사용자가 못 쓴다.**
→ 아카이브 확장보다 §1-2가 우선.
