> 2026-09-06 작성 (ask-matt 전수 탐색). 이 문서는 **페달 회로 밖의 영역** — 픽업, 기타 내부 배선,

## 1. 왜 지금 가능한가 — 기존 자산 점검

새 도메인이지만 **솔버 코어는 거의 건드릴 필요가 없다.** 전수 확인 결과:

| 필요한 것 | 현재 상태 |
|---|---|
| 인덕터 (픽업 코일) | ✅ `core/components/inductor.ts`, transient·AC 양쪽 지원 (`ac.ts:88`) |
| 커패시터 (픽업 자기용량, 케이블, 톤 캡) | ✅ |
| 포텐셔미터 + 테이퍼 (볼륨/톤/블렌드) | ✅ `netlistFromGraph.ts:146` — 저항 2개로 분할, A/B 테이퍼 |
| Op-amp (온보드 프리앰프, 자이레이터 미드) | ✅ GBWP/슬루레이트/레일 클리핑까지 |
| 주파수 응답 (공진 피크 시각화) | ✅ `runAcAnalysis` + `FrequencyResponse.tsx` |
| **스위치** | ❌ 없음 — 신규 필요 |
| **픽업 (합성 소자)** | ❌ 없음 — 신규 필요 |
| **상호 인덕턴스** | ❌ 없음 — §7에서 회피 전략 확정 |

즉 **신규 프리미티브는 2개(`switch`, `pickup`)뿐**이고, 둘 다 포텐셔미터와 같은
"캔버스에서는 1개 부품, 넷리스트로 갈 때 기본 소자 여러 개로 전개" 패턴으로 구현 가능하다.
**솔버·MNA·Newton은 한 줄도 안 바뀐다.**

## 2. 선행 리팩토링 (blocking) — `role` 플래그

`netlistFromGraph.ts:161`이 입력 신호원을 이렇게 찾는다:

```ts
const inputSourceId = parts.find((p) => p.type === "vsource")?.id ?? null;
```

**"배열에서 처음 발견되는 vsource"** 다. 픽업은 내부에 전압원을 품으므로 이 휴리스틱과 즉시 충돌한다.
ROADMAP §6이 트랜지스터 게인 블록을 보류한 것도 같은 이유(자체 Vdd 바이어스 소스와 충돌)였다 —
**이 리팩토링 하나가 픽업·트랜지스터 게인 블록·파워서플라이 블록 세 개를 동시에 푼다.**

제안:

```ts
// editor/types.ts
export interface PartInstance {
  // ...
  /** 이 전압원이 회로에서 하는 역할. 미지정이면 기존 동작(첫 vsource가 입력)을 유지한다. */
  role?: "signalSource" | "supply" | "bias";
}
```

- `inputSourceId` 결정 순서: `role === "signalSource"`인 파트 → (없으면) 기존 첫 vsource 폴백.
- `powerDraw.ts`는 이미 "오디오 입력이 아닌 전원 소스"를 추정 중 — `role`로 교체하면 정확해진다.
- `circuitStorage`는 옵셔널 필드 추가라 **schemaVersion 변경 불필요** (구버전 데이터는 `role` 없음 = 기존 동작).

## 3. 신규 프리미티브 1 — `switch`

**핵심 설계: 스위치를 솔버 소자로 만들지 않는다.** 넷리스트 변환 시점에 **저항으로 스탬프**한다.

- ON = `1e-3 Ω`, OFF = `1e9 Ω` (상수는 `SWITCH_ON_OHMS` / `SWITCH_OFF_OHMS`로 명명)
- 이러면 MNA 행렬 조건수만 신경 쓰면 되고, 비선형 해석도 필요 없다.
- 포텐셔미터가 저항 2개로 쪼개지는 것과 **정확히 같은 패턴** — 이미 검증된 길.

| 스위치 종류 | 단자 | 용도 |
|---|---|---|
| SPST | 2 | 킬 스위치, 코일 탭(한 코일을 접지로 단락) |
| SPDT (3-way 토글) | 3 | 2픽업 셀렉터 (텔레/레스폴 스타일) |
| DPDT (푸시풀 포트) | 6 | 직/병렬, 위상 반전, 스플릿 |
| 4PDT | 8 | 트루 바이패스 풋스위치 |
| 5-way 블레이드 | 2-pole × 5-position | 스트랫 스타일 셀렉터 |
| 로터리 | 1-pole × N | 6-way 배리톤/커스텀 |

- 파라미터: `poles`, `positions`, `position`(현재 위치, 0-base).
- 심볼: `symbols.tsx`에 SPST/SPDT/DPDT 3종 추가 (5-way·로터리는 DPDT 심볼 + 위치 라벨로 재사용).
- **인스펙터에서 `position`을 드롭다운/세그먼트 컨트롤로 노출** — 이게 이 기능의 UX 전부다.
  스위치를 돌리면 주파수 응답이 즉시 다시 계산돼야 한다(`acResult`가 이미 `graph` 변경에 반응하므로 자동).

## 4. 신규 프리미티브 2 — `pickup`

일렉기타 마그네틱 픽업의 표준 등가회로는 **직렬 RL + 병렬 C**다:

```
(신호) Vs --- Rdc --- L ---+--- out
                           |
                          Cp
                           |
                          GND
```

- `Rdc`: 코일 DC 저항
- `L`: 코일 인덕턴스
- `Cp`: 권선 간 자기용량

넷리스트 전개 시 `vsource`(role=signalSource) + `resistor` + `inductor` + `capacitor` 4개로 펼친다.
캔버스에서는 1개 부품(2단자: hot / ground).

**이 모델이 만드는 것**: `L`과 (`Cp` + 케이블 용량 + 포트 부하)가 만드는 **공진 피크**.
공진 주파수는 대략 `f ≈ 1/(2π√(L·C))`이고, 그 Q는 부하 저항(볼륨/톤 포트 값, 앰프 입력 임피던스)이 결정한다.
"왜 험버커에는 500k 포트를 쓰는가", "왜 긴 케이블은 고음을 죽이는가"가 **그래프로 바로 설명된다** —
이 앱이 이미 가진 AC 해석 + 주파수 응답 패널이 그대로 쓰인다.

### 4-1. 픽업 모델 라이브러리 (`PICKUP_MODELS`)

`deviceModels.ts`의 `DIODE_MODELS`/`OPAMP_MODELS`와 동일한 형태로 추가.
아래는 **구현 세션에서 공개 자료로 검증한 뒤 확정할 대표값 스케치**다 (측정치 아님, 값은 반드시 재확인):

| 모델 | L | Rdc | Cp | 비고 |
|---|---|---|---|---|
| 빈티지 싱글코일 (넥) | ~2.2H | ~5.8k | ~100pF | 공진 높고 부드러움 |
| 핫 싱글코일 | ~3.5H | ~8k | ~120pF | |
| 텔레 스타일 브릿지 싱글 | ~2.8H | ~6.5k | ~110pF | 베이스플레이트 영향은 별도 |
| P90 스타일 | ~5.5H | ~8.2k | ~130pF | |
| PAF 스타일 험버커 | ~4.4H | ~7.5k | ~150pF | 코일 2개 직렬 등가 |
| 핫/세라믹 험버커 | ~7.5H | ~14k | ~180pF | 공진 더 낮음 = 어두움 |
| 재즈베이스 스타일 싱글 | ~2.5H | ~7.5k | ~100pF | |
| P베이스 스타일 스플릿 | ~5.5H | ~11k | ~130pF | |
| 액티브 (프리앰프 내장) | — | 출력임피던스 ~10k | — | §6-3 참고, 공진 없음 |

> 검증 출처 후보: Helmuth Lemme의 픽업 임피던스 측정 자료, guitarnuts/buildyourguitar의 공개 측정
> 스레드, 제조사 공개 스펙(DC 저항). **값은 "기능적 사실"이라 참조 가능하나, 문서 문구·이미지는
> 복제하지 않고 `archive.sourceRefs`에 출처만 남긴다** — 페달 프리셋과 동일 원칙.

### 4-2. 험버커 = 픽업 소자 2개

코일 스플릿과 직/병렬을 제대로 다루려면 험버커를 **코일 2개**로 모델링해야 한다.
"험버커(코일 2개)" 프리셋에서 픽업 소자 2개(각 ~2.2H / ~3.75k)를 DPDT로 묶는 형태.

| 스위칭 | 등가 | 소리 |
|---|---|---|
| 직렬 (기본) | L↑ R↑ → 공진 ↓ | 굵고 출력 큼 |
| 병렬 | L/2 R/2 → 공진 ↑ | 밝고 얇음, 출력 -6dB |
| 스플릿 (한 코일 단락) | 코일 1개 | 싱글코일에 가까움 |

**⚠ 정확도 한계**: 두 코일 사이 **상호 인덕턴스**(결합계수 k)를 현 솔버가 표현하지 못한다.
직렬은 실제로 `L1+L2+2M`이므로 단순 합보다 크다. §7-1의 회피 전략 참고.

## 5. 케이블 · 앰프 입력 부하

패시브 픽업에서 톤을 가장 크게 바꾸는 게 **부하**다. 별도 소자 없이 R/C 조합으로 충분하지만,
초보자가 직접 배선하게 두지 말고 **"케이블/앰프 부하" 블록**으로 제공한다.

- 케이블 커패시턴스: 대략 100~150 pF/m → 3m ≈ 300~450pF, 6m ≈ 600~900pF. 길이 슬라이더로 노출.
- 앰프/페달 입력 임피던스: 튜브 앰프 1MΩ, 일반 버퍼 1MΩ, 일부 페달 470k, **퍼즈페이스류 ~10k**.
- 데모 가치: "같은 픽업 + 3m 케이블 vs 6m 케이블" 주파수 응답 겹쳐 그리기 → 즉시 납득되는 A/B.

## 6. 노브 · 톤 회로 · 온보드 EQ

### 6-1. 패시브 톤/볼륨 (기존 소자로 즉시 구현 가능)

| 회로 | 구성 | 시뮬레이션 가치 |
|---|---|---|

| 트레블 블리드 A (캡만) | 볼륨 포트 in↔wiper에 ~680pF~1nF | 볼륨 줄일 때 고음 유지 |
| 트레블 블리드 B (캡 ∥ 저항) | 캡 + 병렬 저항 | 테이퍼 곡선이 A와 다름 |
| 트레블 블리드 C (캡 + 직렬 저항) | 캡 + 직렬 저항 | 세 방식의 차이를 그래프로 비교 |
| **50s 배선 vs 모던 배선** | 톤 캡을 볼륨 wiper 쪽 vs 입력 쪽 | **순수 토폴로지 차이 → 시뮬레이터의 최고 소재** |

| PTB (패시브 트레블/베이스) | 톤 + 베이스컷 직렬 | 베이스/G&L 계열 |

### 6-2. 온보드 액티브 EQ

기존 `active-shelf-eq.ts`가 출발점. op-amp가 이미 비이상성까지 모델링되므로 그대로 확장 가능.

- **Baxandall 2밴드** (베이스/트레블 셸빙) — 액티브 온보드 프리앰프의 표준 토폴로지.
- **3밴드 (미드 벨 추가)** — 미드 밴드는 실물에서 **자이레이터**(op-amp + RC로 인덕터 흉내)를 쓴다.
  이 앱에는 진짜 인덕터도 있으니 **자이레이터 버전과 실인덕터 버전을 나란히 시뮬레이션해
  등가임을 보여주는 데모**가 가능하다 — 교육 콘텐츠로 강력함.
- **버퍼/임피던스 매칭 단** — 온보드 프리앰프가 왜 케이블 길이에 둔감한지 §5와 묶어서 A/B.
- 전원: 9V 배터리 = `vsource` + `role: "supply"` (§2 리팩토링 후 안전).

### 6-3. 액티브 픽업

내부 프리앰프가 있어 **출력 임피던스가 매우 낮고 공진 피크가 없다**.
모델: `vsource(role=signalSource)` + 직렬 R(~10k), L/C 없음.
"패시브 vs 액티브를 같은 케이블·같은 페달에 물렸을 때" A/B가 곧바로 나온다.

## 7. 솔버 한계 — 정직하게 범위 밖으로 둘 것

과설계 방지를 위해 **처음부터 못 하는 것을 명시**한다 (ROADMAP §6의 "손댈 필요 없다고 판단한 부분"과 같은 취지).

1. **상호 인덕턴스 없음.** 코일 간 결합, 트랜스포머(옥타비아류) 표현 불가.
   - **v1 회피 전략**: 스위칭 상태별 **등가 L/R을 테이블로 미리 계산해 넣는다.**
     (직렬 = 문헌 기반 등가 L, 병렬 = 등가 L, 스플릿 = 단일 코일 L). 정확도 충분, 구현 비용 0.
   - v2에서 필요하면 `inductor.ts`에 상호 인덕턴스 항 스탬프 추가 — **별도 항목으로 분리**.
2. **험 캔슬링은 시뮬레이션 안 됨.** 험버커가 노이즈를 지우는 건 자기적 현상이라 회로 해석에 안 나온다.
   노이즈 주입 모델은 별도 대형 작업 → 범위 밖으로 명시하고 UI에도 주석.
3. **현/자석/에디 커런트 등 기계·자기 영역 전부 범위 밖.** 이 앱은 픽업의 **전기적 등가회로**만 다룬다.
4. **`chain.ts`는 로딩 효과를 무시한다** (아래 §8).

## 8. ⚠ 아키텍처 이슈 — 통합 신호 경로와 로딩 효과

이게 이 확장에서 가장 중요한 기술 판단이다.

목표 파이프라인:

```
픽업 → 기타 배선(볼륨/톤/스위치) → 케이블 → 페달 체인 → 앰프 입력 → 캐비닛 IR
```

`chain.ts`는 각 스테이지의 출력 파형을 **다음 스테이지의 이상적 입력 소스**로 넘긴다.
즉 **뒷단이 앞단에 거는 부하를 무시한다.** 페달끼리는 대개 버퍼가 있어 괜찮지만,
**패시브 픽업 → 첫 페달** 구간은 정확히 그 로딩이 핵심이다:

- 퍼즈페이스류(입력 임피던스 ~10k)가 기타 볼륨 노브에 극적으로 반응하는 이유
- 앞에 버퍼를 두면 그 반응이 사라지는 이유
- 케이블/포트가 공진을 이동시키는 이유

**결론: 기타 배선 + 첫 페달은 "체인"이 아니라 "하나의 넷리스트로 병합"해서 풀어야 한다.**

- 구현: `netlistFromGraph`가 이미 union-find로 그래프 전체를 하나의 넷리스트로 만든다 →
  **같은 캔버스에 기타 배선과 페달을 함께 놓으면 자동으로 병합된다.** 추가 작업 거의 없음.
- 필요한 것은 UI 쪽 — "기타 섹션"과 "페달 섹션"을 시각적으로 구분(Phase 5 기능 블록 시스템 재사용)
  하고, 캔버스가 커지므로 뷰포트 관리(fit-to-view, 미니맵)가 선행돼야 한다.
- `chain.ts`는 **버퍼가 있는 페달 간 연결에만** 쓰도록 용도를 문서에 명시하고,
  기타→첫페달 구간에 쓰면 부정확하다는 경고를 ChainPanel에 노출한다.

## 9. 배선 구성 프리셋 목록

페달 프리셋(`PedalPreset`)과 같은 포맷을 재사용하되, `PresetCategory`에 기타 배선 계열을 추가한다.
`LibraryExplorer`의 최상위를 "페달 프리셋 / 기능 블록" 2그룹에서 **"기타 배선"을 더한 3그룹**으로 확장.

| # | 프리셋 | 다루는 개념 |
|---|---|---|
| 1 | 싱글 픽업 + 볼륨 + 톤 | 가장 단순한 기준 회로 |
| 2 | 3-way 토글 (험버커 2개) | SPDT 셀렉터, 독립 볼륨·톤 |
| 3 | 3-way + **50s 배선** | §6-1의 50s vs 모던 A/B |
| 4 | 5-way 블레이드 (싱글 3개) | 2-pole 5-position, 하프톤 포지션 |
| 5 | 텔레 스타일 3-way (볼륨+톤 공유) | 브릿지/넥 병렬 |
| 6 | **코일 스플릿 (푸시풀)** | DPDT로 한 코일 접지 단락 |
| 7 | **직렬/병렬 전환** | 험버커 두 코일, 또는 넥+미들 |
| 8 | **위상 반전 (아웃오브페이즈)** | DPDT로 한 픽업 극성 반전 |
| 9 | 트레블 블리드 3종 비교 | §6-1 표 |
| 10 | 재즈베이스 스타일 (볼륨 2 + 마스터 톤) | 두 볼륨의 상호작용 |
| 11 | P/J 배선 | 임피던스가 다른 픽업 혼용 |
| 12 | 블렌드 포트 배선 | 포텐셔미터 응용 |
| 13 | 온보드 액티브 2밴드 | §6-2 |
| 14 | 온보드 액티브 3밴드 (자이레이터 미드) | §6-2 |
| 15 | 킬 스위치 / 노로드 톤 | SPST 응용 |

**위상 반전 주의**: 회로적으로는 픽업의 hot/ground를 바꾸는 것이고, `pickup` 소자에
`invertPhase` 파라미터(전개 시 vsource 극성 반전)를 두면 DPDT 없이도 표현 가능.
다만 실물 배선을 재현하는 게 목적이면 DPDT로 그리는 쪽이 교육적이다 — **두 방식 다 제공**.

## 10. 페이즈 계획

ROADMAP의 Phase 0~8 뒤에 이어붙인다.

| 페이즈 | 내용 | 선행 조건 |

| 10 | **스위칭 & 배선** — `switch` 소자(SPST/SPDT/DPDT/5-way) + 심볼 + 인스펙터 위치 컨트롤 → 배선 프리셋 1~8 | 9 |
| 11 | **노브 & 톤 회로** — 실시간 노브 슬라이더, 파라미터 스윕 겹쳐 그리기, 트레블 블리드/50s 프리셋 9 | 10 |
| 12 | **온보드 액티브** — Baxandall 2/3밴드, 자이레이터 미드, 액티브 픽업, 프리셋 13~14 | 9 |
| 13 | **통합 신호 경로** — 기타+페달 동일 캔버스 병합 해석, 섹션 시각 구분, ChainPanel 로딩 경고 | 10, UI 트랙의 fit-to-view |

### 실행 순서 (Phase 9 첫 루프)

1. `role` 플래그 도입 + `inputSourceId` 결정 로직 교체 + 기존 173개 테스트 그린 유지
2. `pickup` 파트 타입 (partDefs / netlistFromGraph 전개 / symbols / BOM 취급 결정)
3. `PICKUP_MODELS` — 공개 자료 검증 후 값 확정, 인스펙터 모델 드롭다운에 편입 (`MODEL_MENUS` 재사용)
4. "케이블 + 앰프 입력" 블록 (`blockDefs.ts`)
5. 프리셋 1(싱글 픽업 + 볼륨 + 톤) 추가 → `presets-sanity.test.ts`에 자동 편입
6. 전용 테스트: 공진 주파수가 `1/(2π√(LC))` 근사와 일치하는지, 케이블 용량을 키우면 공진이
   낮은 쪽으로 이동하는지 (AC 해석 기반, 기존 `tests/solver/ac.test.ts` 패턴 재사용)

## 11. 저작권 / 표기 원칙

페달 아카이브와 **동일 원칙 적용** ([plan-circuit-archive.md](./plan-circuit-archive.md) §2):

- 배선도 이미지·설명 문구 복제 금지. 토폴로지와 대표 부품값(기능적 사실)만 참고해 직접 넷리스트 재작성.
- 상표명 대신 스타일 표기: "스트랫 스타일 5-way", "PAF 스타일 험버커", "레스폴 스타일 50s 배선".
- 각 배선 프리셋에 `archive.sourceRefs` + `disclaimer` 부착.
- 픽업 파라미터는 "대표 근사값이며 특정 제조사 제품의 실측값이 아님"을 disclaimer에 명시.
